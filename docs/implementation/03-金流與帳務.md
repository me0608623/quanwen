# 03 · 金流與帳務

> 範圍：`apps/api/src/wallet`、`point-shop`、`spin`、`mutual`
> 來源：原始碼盤點（2026-06-15）
> ⚠️ 金流紅線：金額一律 integer NT$ 無 float；每筆交易雙向 journal entry（debit = credit）

| 方法 | 路徑 | 用途 |

## 2. 雙向記帳模型

**交易類型**（`transaction_type` enum）：`deposit`、`reward_out`、`reward_in`、`platform_fee`、`withdraw_request`、`withdraw_complete`、`refund`、`points_in`、`points_spend`

**交易狀態**（`transaction_status`）：`pending`、`processing`、`success`、`failed`、`cancelled`

**帳戶科目**：
- 托管：`escrow_ecpay`、`escrow_mock`、`survey_escrow`（= `wallets.locked_cash`）、`withdraw_pending`
- 用戶：`wallet_<userId>`（= `cash_balance`）、`points_wallet_<userId>`
- 收入/中間：`reward_payable`（理論為 0）、`platform_revenue`、`points_liability`

**記帳範例（發獎 NT$100 + 10% 手續費）**：
```
fee = ceil(100 × 0.10) = 10；unitCost = 110
T1 reward_out  110  DR survey_escrow / CR reward_payable
T2 reward_in   100  DR reward_payable / CR wallet_<respondent>
T3 platform_fee 10  DR reward_payable / CR platform_revenue
```

## 3. 費用計算與金流（`wallet.service.ts`）

**常數**：`PLATFORM_FEE_RATE = 0.10`（2026-06-07 由 15% 調降）、`MIN_WITHDRAWAL = 300`、`MAX_DAILY_WITHDRAWAL = 30_000`、`POINTS_VALUE_NTD = 0.5`

**費用公式**（逐份進位，非總額 ×1.1）：
```ts
feeFor(reward)     = Math.ceil(reward × 0.10)
unitCostFor(reward) = reward + feeFor(reward)
// reward=6 → fee=1 → unit=7（不是 6.6）
```

**預算鎖定**（`lockSurveyBudget`，發布時）：`totalBudget = unitCostFor(rewardPoints) × targetCount`，`lockAmount = min(totalBudget, cashBalance)`，原子：`cashBalance -=`、`lockedCash +=`、寫 transaction(reward_out, pending) + journal `DR wallet / CR survey_escrow`。

**預算解鎖**（`unlockSurveyBudget`，關閉時）：`actualPaid = completedCount × unitCostFor(reward)`，`refund = max(0, totalLocked − actualPaid)` 退回現金 + journal `DR survey_escrow / CR wallet`。

**發獎**（`issueReward`，提交時）：優先扣 `survey_escrow`（lockedCash），不足走 cashBalance；餘額不足 → status=pending 等人工補款；防重複用 `UNIQUE(relatedResponseId, type)`；樂觀鎖 version + SELECT FOR UPDATE。

## 4. ECPay 儲值 / 提領

**儲值**（限額 NT$100–100,000）：建 transaction(deposit, pending) → MerchantTradeNo `QW + txn.id[:18]` → SHA256 CheckMacValue → 回自動提交 HTML → callback 驗 HMAC + `rtnCode=1` → 原子入帳（UPDATE WHERE status=pending 保冪等）→ 回 `1|OK`。冪等鍵 `UNIQUE(external_provider, external_ref)`。
- env：`ECPAY_MERCHANT_ID`、`ECPAY_HASH_KEY`、`ECPAY_HASH_IV`、`ECPAY_PAYMENT_URL`

**提領**：驗 ≥ NT$300 → 金額 ≥ NT$2,000 觸發 KYC 檢查（須 approved）→ 驗餘額 + 當日累計 ≤ 30,000 → 原子 `cashBalance -=`、`lockedCash +=`（暫鎖）、INSERT transaction(withdraw_request, pending) + 加密銀行帳號/姓名。Admin 核准 → `withdraw_complete` + journal；拒絕 → 退回 cashBalance。

## 5. 互惠問卷配對（`mutual.service.ts`）

**狀態**（`mutual_pair_status`）：`waiting → matched → a_done/b_done → both_done`、`expired`、`cancelled`

**配對 cron**（`matchWaitingPairs`，`@Cron(EVERY_30_SECONDS)`，Redis 鎖 `qw:lock:mutual-match`）：
- 拉 `status=waiting` 按 createdAt 排序，<2 對則跳過
- 配對優先序：同 category 不同 user 最早 → FIFO 任意不同 user → 避免自配
- `matchTwoWaitingPairs`：原子更新 A 為 matched + 設 expiresAt（now+72h）+ 刪 B，雙方發「互惠配對成功」通知

> ⚠️ 已知坑：Render free 閒置休眠時 30s cron 不跑 → 配對卡 waiting、不發通知（GitHub issue #126）。

**超時 cron**（`expireOverduePairs`，`@Cron(EVERY_MINUTE)`，`MUTUAL_TTL_MS = 72h`）：matched/a_done/b_done 超時 → expired + 通知。

**填答**（`submitMutualResponse`）：AI 品質閘門（rejected → reputation −3 + 取消配對；passed → +1）；`markFilled` 雙方填完 → both_done 解鎖互看；完成發 1 次轉盤機會。**互評**（`rateOther`，both_done 後）：rating≥4 對方 +2、≤2 −3、=3 +0。**外部連結互惠**：`submitProof` 上傳完成截圖。

## 6. 轉盤（`spin.service.ts`）

**Endpoint**：`GET /spin/status`、`POST /spin`（限流 2/s、20/min）

**獎項**（`SPIN_SEGMENTS`，2026-06-07 重配，期望值 ≈ 6.56 點/轉 ≈ NT$3.3）：1點(24%)、3點(22%)、5點(18%)、銘謝惠顧(12%)、8點(12%)、15點(6%)、30點(3%)、50點(2%)、大獎100點(1%)

**流程**：驗 `available>0` → 加權隨機 → 原子（`available-=1, spentTotal+=1` WHERE available>0；中獎呼叫 `wallet.grantPoints`；INSERT spinRecords）。觸發來源：完成問卷 / 完成互惠填答各 `grantChance(userId, 1)`。

## 7. 積分商城（`point-shop.service.ts`）

**Endpoint**：`GET /shop/items`、`/my-redemptions`、`POST /shop/redeem/:itemId`、`/my-redemptions/:id/mark-used`

**兌換**：先發券（http provider 呼供應商 API 拿 code，失敗不扣點）→ 加密 PIN（AES-256-GCM）→ 原子（`pointsBalance -= cost` WHERE 足夠、transaction(points_spend) + journal `DR points_wallet / CR points_liability`、INSERT pointRedemptions(issued, 預設 6 個月效期)、`stockQty -= 1`）。商品分類：`voucher_711/familymart/starbucks/general`、`merchandise`。

## 8. 對帳（`reconciliation.service.ts`）

每日 `runDaily`，七大不變式：
1. 每筆 transaction 借貸平衡（journal 借=貸）
2. `wallets.cash_balance` = journal `wallet_*` 餘額
3. `wallets.locked_cash` = journal `survey_escrow` 餘額
4. `reward_payable` 餘額 = 0（中間帳）
5. 托管帳平衡（escrow = 用戶 + 費用）
6-7. 其他帳戶一致性

不變式失敗 → log error + `alertAdmins`（發 system 通知給所有 admin，標題「🚨 對帳異常」）。
