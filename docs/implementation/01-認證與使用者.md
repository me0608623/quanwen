## 2. JWT

- **Payload**：`{ sub: userId, email, role }`（`jwt.strategy.ts`）
- **密鑰**：`JWT_SECRET`（≥ 32 字元，CLAUDE.md 要求 ≥ 64）
- **有效期**：`JWT_EXPIRES_IN ?? '7d'`，演算法 HS256
- **驗證流程**：提取 Bearer → 驗簽 + 不忽略過期 → 用 `sub` 查 DB → 檢查 `status='active'` 且 `deletedAt IS NULL` → 注入 `req.user`（`AuthenticatedUser`）
- **Token 刷新**（Phase P）：有效 token 內可 `POST /auth/refresh` 重簽 7 天，免重新登入。程式註解提及未來可改短期 access + refresh table。

## 3. OAuth 三個 provider 的做法差異

| Provider | 機制 | email 取得 | 特點 |
|----------|------|-----------|------|
| **Google** | Passport `google-oauth20` | Google Profile API | Passport 自動驗 state/CSRF |
| **LINE** | 手動 fetch + state 驗證（5 分鐘 TTL login state） | 優先 id_token email claim，無則 `line_${userId}@line.placeholder` | nonce 用 CSPRNG 產生 |
| **Apple** | 動態 client secret（ES256 簽）+ `jose` 驗 id_token RS256 | 優先 id_token，無則 `apple_${sub}@apple.placeholder` | `response_mode=form_post`（POST callback）；只首次授權回 user name |

**Apple client secret 動態產生**：JWT header `{alg:ES256, kid:APPLE_KEY_ID}`，payload `{iss:TEAM_ID, sub:CLIENT_ID, aud:appleid.apple.com, iat, exp+3600}`，ES256（P-256）IEEE-P1363 格式。

**Apple id_token 驗證（Phase K.4）**：改用 `jose` 驗 RS256 簽章 + 驗 `iss/aud/exp`，從 Apple JWKS 取公鑰（舊做法直接 base64 decode 易偽造）。

## 4. 帳號綁定流程

- **Bind session**：10 分鐘 TTL，存內存 Map（`stateToken → {userId, provider, expiresAt}`），重導時 state = `bind:${stateToken}`（前綴區分 login vs bind）
- **防搶奪**：OAuth 帳號已被別的 quanwen 帳號綁 → `ConflictException`（不 auto-link）
- **安全規則**（CLAUDE.md）：`findOrCreateOAuthUser` 不依 email 自動連結既有帳號，一律新建（email 撞號用 `@oauth.quanwen.local` fallback）；要合併須先登入既有帳號再從設定綁定
- **成功後**：bind → `/settings/accounts?bound=${provider}`；login → `/auth/callback?token=...`

## 5. 密碼政策

來源：`auth.controller.ts: validatePasswordPolicy` + `auth.service.ts: validatePasswordStrength`（controller + service 雙層）

- 長度 8–72 字元（72 = bcrypt 限制）
- 至少 1 個大寫字母、至少 1 個數字
- 雜湊：bcryptjs，rounds = 12，存 `users.password_hash`

## 6. Email 驗證 / 密碼重設

- 驗證 token：48-byte random，24h TTL，連結 `${WEB_URL}/auth/verify-email?token=`
- 重設 token：48-byte random，1h TTL；`forgot-password` 一律回 200（防 email 枚舉）

## 9. KYC

來源：`apps/api/src/kyc/`

| 方法 | 路徑 | 用途 |
|------|------|------|
| GET | `/kyc/me` | 自己的 KYC 狀態（不解密 PII） |
| POST | `/kyc/submit` | 提交（身分證/姓名/手機/證件照），觸發多帳號偵測 |
| GET | `/admin/kyc` | 待審清單（含解密 PII，僅 admin） |
| POST | `/admin/kyc/:id/approve` · `/reject` | 核准 / 駁回 |

- **狀態**：`unverified → submitted → approved/rejected`（可重交）
- **觸發**：提領 ≥ NT$2,000（`KYC_REQUIRED_THRESHOLD = 2000`）
- **驗證**：身分證 `^[A-Z][12]\d{8}$`、手機 `^09\d{2}\d{6}$`、姓名 2–50 字
- **PII 加密**：`id_number_cipher`/`real_name_cipher`/`phone_cipher` 走 AES-256-GCM；證件 URL 不加密
- **審核防護**：禁止 admin 核准/駁回自己的 KYC；多帳號偵測 fire-and-forget

## 10. Common 層橫切關注點

來源：`apps/api/src/common/`、`main.ts`

- **ZodValidationPipe**（全域）：所有 DTO 用 Zod 驗證，失敗回 field-level errors
- **GlobalExceptionFilter**（全域）：統一錯誤格式 `{success, statusCode, requestId, timestamp, path, message}`；PostgreSQL `22P02`（無效文字）特判為 400；≥500 記 error log 含 stack
- **ThrottlerGuard**（全域 APP_GUARD）：short（1s/10）+ medium（60s/100），`RedisThrottlerStorage`（Lua INCR+PEXPIRE 原子），Redis 故障降級 in-memory
- **JwtAuthGuard**：大多數端點認證
- **AiQuotaGuard** + `@AiQuota('feature')`：AI 配額把關，VVIP 無限，超限回 403 含 `{used, limit, remaining}`
- **CryptoService**：`encrypt/decrypt/tryDecrypt`（`v1:iv:tag:ct` 自描述格式）+ `redactPii`（去識別化 `[CARD]/[ID]/[PHONE]/[BANK]/[EMAIL]`）；金鑰 `PII_ENCRYPTION_KEY` 經 scrypt KDF
- **RedisService**：動態 import ioredis，無 `REDIS_URL` 則 client=null，懶初始化
- **UploadController**：`POST /upload/image`（5MB，JPEG/PNG/GIF/WebP/SVG）、`DELETE /upload`
- **HealthController**：`GET /health`（liveness，永遠 200）、`GET /ready`（readiness，DB+Redis strict，任一 down 回 503）
- **main.ts 安全**：Request ID 追蹤、Helmet（CSP prod only）、CORS 白名單（`WEB_URL` + `CORS_ORIGINS`）、`/uploads/*` 靜態、API prefix `/api/v1`（排除 health/ready）
