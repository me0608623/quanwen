## 2. 問卷狀態機與發布流程

**狀態**（`survey_status` enum）：`draft`、`pending_review`、`published`、`paused`、`closed`、`rejected`

**發布流程**（`surveys.service.ts:411-487`）：
1. 驗證所有者 + 必須是 draft；抽獎卷需 `lotteryTermsAcceptedAt`
2. **外部問卷**（有 `externalUrl`）：跳過題目要求/AI 審核/預算鎖定，直接 published
3. **互惠問卷**（`type='mutual'`）：簡易 PII 過濾，跳過 AI 審核/預算鎖定，直接 published 並進配對池
4. **標準問卷**：`aiReviewEnabled=false` 直接上架（仍鎖預算）；`true`（預設）→ published 後 fire-and-forget AI 掃描（advisory，不擋發布）
5. **預算鎖定**：fire-and-forget 呼叫 `walletService.lockSurveyBudget`

**已發布資訊編輯白名單**（`surveys.service.ts:267-296`）：`title`、`description`、`category`、`coverImageUrl`、`welcomeImages`、`theme`、`thankYouMessage`、`thankYouImages`、`thankYouRedirectUrl`、`audienceCriteria`。題目/選項/獎勵/抽獎/邏輯規則鎖定。

> ⚠️ 已知坑：`UpdateSurveySchema` 用 Zod `.partial()` 但 base schema 欄位帶 `.default()`，`.partial()` 不移除 default，導致只送 theme 也被白名單擋（見 GitHub issue #139）。

**排程與自動關閉**（`survey-scheduler.service.ts`，cron 每分鐘）：排程發布（`scheduledPublishAt`）、時間自動關閉（`autoCloseAt`）、配額自動關閉（`completedCount >= autoCloseAfterN`）。

## 4. 品質審核三層管線

來源：`responses/quality-audit.service.ts`、`anti-cheat.service.ts`

**Layer 1 — 反作弊**（`anti-cheat.service.ts`，分數 0-100 越高越可疑）：
- 填答速度（`MIN_SECONDS_PER_QUESTION=3`）：極快 +50、偏快 +25
- 文字題速度（`<2s` 累計最多 +30）、文字品質（短答 +20、重複字元 +30、鍵盤連續 +25、亂碼 +20）
- 選擇題全選同選項（≥4 題）+15、回答題數不足（<0.5）+15

**Layer 2 — 行為加權**（轉 0-100 behaviorScore）：timing 5%、attention check 20%、reverse consistency 15%、text quality 15%、choice pattern（=100-antiCheat）、completion 懲罰

**Layer 3 — LLM judge**：觸發條件 `40 ≤ behaviorScore < 75`（灰色地帶）。`HOLISTIC_JUDGE` prompt 輸出 `{sincerity_score, recommendation: approve|manual_review|reject, primary_concern, summary, evidence[]}`

**最終裁決**（`finalScore = behaviorScore×0.4 + llmScore×0.6`）：
- `<50` 或 llm reject → **rejected**（不發獎、扣信譽）
- `50-79` 或 llm manual_review → **suspicious**（人工複核）
- `≥80` 且非 reject → **passed**（自動發獎）
- 邊緣救回：`40≤finalScore<50` 且 `textQuality≥70` 且非 reject → 降為 suspicious

## 5. 統計分析（`analytics.service.ts`）

| Endpoint | 分析 | 方法 |
|----------|------|------|
| `/analytics/descriptive` | 描述統計 | mean/median/mode/stddev/min/max |
| `/analytics/scale-reliability` | 量表信度 | Cronbach's α + alpha-if-deleted + 反向題自動反轉（`reverse(x)=min+max-x`） |
| `/analytics/cross-tab` | 交叉分析 | 列聯表 + Cramér's V |
| `/analytics/nps` | NPS | Promoters(9-10) − Detractors(0-6) |
| `/analytics/correlation` | 相關 | Pearson r |
| `/analytics/group-comparison` | 分組比較 | 2 組 Welch t / ≥3 組單因子 ANOVA + Cohen's d |
| `/analytics/regression` | 複迴歸 | 係數、β、t/p、R²/調整 R² |
| `/analytics/segmentation` | 分群 | K-means（預設 k=3） |

> 進階統計每個指標各耗 1 次 analyze_responses 額度，後端先重算確定性統計再交 LLM 白話解讀。
> ⚠️ 規劃中：信度分析升級為 JASP 式三柱即時介面 + McDonald's ω（GitHub issue #143）。

## 6. 匯出格式（`export.service.ts`）

- **PDF**：統計總覽（pdfmake，嵌 Noto Sans TC）
- **Excel**：Sheet1 Responses + Sheet2 Summary（exceljs，含 buffered 與 streaming WorkbookWriter）
- **CSV**：UTF-8 BOM、keyset 分頁 500 筆/批、串流常數記憶體
- **Markdown**：聚合統計報告
- **JASP/SPSS**：數值編碼 + Value Labels + 多選題 0/1 拆欄（給統計軟體）
- **cleanOnly**（`clean=1`）：只留 `qualityScore >= minScore`（預設 70），不含 rejected/未審核
- 文字答案匯出前過 `redactPii()`；加密題顯示 PLACEHOLDER

## 7. AI 洞察報告（`ai-insights.service.ts`）

流程：`getSurveyStats` → 雙層 cache（L1 in-process + L2 Redis）→ 樣本量檢查（<3 fallback）→ LLM → JSON 解析 → 結構化回傳，並持久化到 `survey_ai_reports`（重查不耗額度）。

- **Simple**：summary(≤300)、keyFindings(≤6)、concerns(≤4)、recommendations(≤5)
- **Detailed**：加 questionBreakdown(≤30 逐題)、crossFindings(≤8)、methodology（方法/信賴度說明），各上限放大
- **Fallback**：樣本<3 或 LLM 失敗 → 規則生成（不進 cache）
- **情緒分析**：`analyzeTextSentiment`（主題萃取）、`analyzeResponseSentiments`（逐筆，PII 遮蔽）
- **統計解讀**：`interpretStatistics` 把迴歸/ANOVA 等白話化，固定附注「發表用請以 JASP/SPSS 驗證」

> ⚠️ 已知坑：洞察生成「產生洞察失敗」八成非 LLM（analyze 有 fallback），疑 `survey_ai_reports` schema drift（GitHub issue #118）。

## 8. 跳題邏輯與題型

- **題型**（`question_type` enum）：`single_choice`、`multiple_choice`、`text`、`rating`、`matrix`
- **跳題邏輯**（`survey_logic_rules` 表）：condition（eq/neq/gt/gte/lt/lte/contains/…）+ action（show/hide/skip），轉 SurveyJS `visibleIf`
- **題目隨機化**（QUA-204）：`randomizationSeed` 各自播種
